About 21K School

21K School is an India-born, globally oriented online school. It delivers personalised, technology-enabled education to 7,500+ students across 70+ countries. Its model combines academics, technology and strong parent engagement to create a flexible, learner-centric schooling experience.

The school is backed by Ronnie Screwvala, the entrepreneur, investor and philanthropist who co-founded upGrad. Its stated belief is that a good education should not depend on where a child lives.

For a QA intern this matters. A school serving students in many countries depends heavily on its web and mobile apps. Bugs in those apps affect real learners and parents, so testing is a core function here.

Role Overview

The role is to assist with quality assurance for 21K School's web and mobile applications. You validate features, document defects and support reliable releases. You will work inside the Technology department alongside the people who build and ship the product.

Key responsibilities listed in the posting:

  • Prepare and execute manual test cases based on requirements and acceptance criteria.
  • Perform functional, regression, integration and exploratory testing.
  • Log defects with clear reproduction steps, expected and actual results, and evidence.
  • Retest fixes, maintain defect trackers and help monitor test coverage.
  • Support API testing using tools such as Postman, and assist with UAT and release verification.
  • Learn basic test automation where suitable and follow documented QA processes.

The list shows that the internship is mostly manual testing with some exposure to API testing and a little automation. That is a sensible learning path for a fresher.

You also get exposure to UAT and API testing, which are in demand for QA roles. Working on a product used by students in many countries gives you a realistic view of quality at scale. For a resume, that is more convincing than a generic course certificate.

Preparation Plan

You can prepare well in a week or two. Focus on these steps:

  1. SDLC and STLC: know the phases, and the difference between verification and validation.
  2. Test design: practise writing test cases with preconditions, steps, expected results and priority. Learn boundary value analysis and equivalence partitioning.
  3. Testing types: be able to explain functional, regression, integration, smoke, sanity and exploratory testing with examples.
  4. Defect reporting: learn a clear bug template covering title, steps to reproduce, expected result, actual result, severity and evidence.
  5. Postman basics: send GET and POST requests, read status codes and check response bodies.
  6. Jira basics: understand tickets, statuses and how a bug moves from open to closed.

Practise on a real website or app. Pick a signup or payment flow and write ten test cases for it. Then find two bugs and report them cleanly.

Likely Interview Topics

  • Difference between a bug, defect and failure.
  • Severity versus priority, with examples.
  • What regression testing is and why it matters before each release.
  • How you would test a login page or a video class booking feature.
  • What a 200, 400, 401 and 500 status code mean in API testing.
  • What UAT is and who performs it.
  • Your academic project and how you would test it.

Answer with short, concrete examples. A clear, structured answer matters more than long theory.
