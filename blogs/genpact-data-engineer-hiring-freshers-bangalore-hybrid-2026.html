About Genpact

Genpact is a global professional services and solutions firm that helps organisations run and transform their operations using data, technology and AI. It has a large presence in India, including Bangalore, where many of its data, analytics and technology teams work for clients across industries.

For a fresher, a services firm like this offers exposure to varied client problems, structured delivery processes and a range of data platforms. That breadth helps early in a data engineering career, because you see how pipelines are built, tested, released and supported in real production settings.

Role Overview: What a Data Engineer Does Here

According to the official posting, the role centres on building and running data pipelines under established engineering standards. The listed responsibilities are:

  • Build and maintain data ingestion, ETL and ELT pipelines using approved engineering standards.
  • Implement source-to-target mappings, transformation logic and data processing workflows.
  • Write and maintain SQL, Python, PySpark and platform-specific code.
  • Perform unit testing, data validation, reconciliation and defect resolution.
  • Support deployment, migration and release activities across environments.
  • Create technical documentation, operational runbooks and coding artefacts.
  • Monitor pipelines and resolve operational issues under guidance.
  • Follow data quality, security and engineering governance standards.

Note the phrases "under guidance" and "approved engineering standards". They suggest a role where you implement designs and follow processes rather than architect systems alone, which suits early-career engineers.

Preparation Plan

Week 1: SQL. Practise joins, window functions, CTEs, aggregations, deduplication and query optimisation basics. Data engineering interviews lean heavily on SQL.

Week 2: Python and PySpark. Revisit data structures, file handling, functions and error handling. Then learn DataFrame operations, transformations versus actions, joins, partitions and simple performance ideas in PySpark.

Week 3: Pipelines. Understand ETL versus ELT, source-to-target mapping, incremental loads, data modeling (star schema, facts and dimensions) and data quality checks. Build a small pipeline that reads a public dataset, transforms it and loads it into a database or Delta tables.

Week 4: Tools and revision. Learn what an Airflow DAG is, how Git and GitHub branching works, and the basics of Databricks and Snowflake. Free tiers and community editions are enough for practice. Finish with mock interviews.

Interview Topics to Revise

  • Difference between ETL and ELT, and when to use each.
  • Reconciliation and validation: how you would check that source and target data match.
  • Handling duplicates, nulls and late-arriving data.
  • Spark basics: lazy evaluation, shuffles, partitioning, caching.
  • Airflow concepts: DAGs, tasks, schedules, retries.
  • Git workflow: branch, commit, pull request, merge conflicts.
  • Your projects: be ready to explain every design choice and every bug you fixed.
